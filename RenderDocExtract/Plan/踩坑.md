# 踩坑记录

本文件用于持续记录 RenderDoc EID Draw 资源提取器开发过程中的错误、误判、修复方式和防复发规则。

## 2026-06-06 - 计划阶段明确测试门禁
- 现象：用户补充要求固定测试 EID `7643` 和 `7955`，其中 `7955` 是 instanced Draw。
- 根因：原计划只写了“选择一个可重放 Draw”，没有固定 smoke test，也没有明确 instanced Draw 提取策略。
- 修复：计划中新增固定测试 EID：`7643` 普通 Draw、`7955` Instanced Draw；并规定遇到 instanced 绘制时第一阶段只提取第一个 instance，即 `extracted_instance=0`，同时 manifest 保留原始 `numInstances`。
- 防复发规则：后续每个脚本测试必须覆盖 `7643` 和/或 `7955` 的相关能力；涉及 mesh/manifest 的脚本必须显式记录 instanced Draw 的 `numInstances` 与 `extracted_instance=0`。

## 2026-06-06 - rd_session.py 测试方式误判导致 qrenderdoc 卡住
- 现象：直接用 `qrenderdoc.exe --python rd_session.py` 运行测试后长时间无返回，进程 `qrenderdoc.exe` 常驻并占用大量内存；用户反馈“一直卡着”。
- 根因：当前仓库生成的 `renderdoc.py` 是 qrenderdoc Python 绑定 wrapper，不适合用系统 Python 直接 standalone replay；而直接启动 `qrenderdoc.exe --python` 会进入 qrenderdoc GUI/事件循环或加载大型 RDC，不能作为无交互 headless 单元测试方式。第一次系统 Python 测试也暴露 `renderdoc` 模块缺少 `InitialiseReplay/ShutdownReplay`。
- 修复：已手动结束卡住的 `qrenderdoc.exe` 进程。后续先不再用前台 `qrenderdoc.exe --python` 作为自动测试命令；需要改 `rd_session.py` 支持更明确的运行模式，或改为 renderdoccmd/C++ 接入/可控 qrenderdoc 脚本退出方式。
- 防复发规则：任何可能启动 GUI 或长期 replay 的命令必须先使用短超时/后台可终止方式；测试命令必须能确定退出。若 RenderDoc Python 绑定不支持 standalone replay，不继续硬跑大 RDC，应先修正执行入口。

## 2026-06-06 - extract_mesh.py 将 ATTRIBUTE0 误判为 custom 导致 OBJ 全零
- 现象：导出的 OBJ 文件中顶点都是 `v 0 0 0`，用户用文本打开发现 vertices/triangle 看起来为 0 或全零。
- 根因：EID 7643/7955 的 VS Input 没有传统 `POSITION` semantic，而是 `ATTRIBUTE0` 为 `R32G32B32_FLOAT`。脚本只把 POSITION/POS/ATTRIBUTE 判定为 position，未把 `ATTRIBUTE0` 判定为 position，导致 OBJ preview 使用占位坐标 `0 0 0`。
- 修复：将 `ATTRIBUTE0` 作为 position-like attribute；重跑 EID 7643 和 7955 后生成新的 mesh：`mesh_e104e718b4faa2e7` 和 `mesh_ab402735f71d4cad`，OBJ 顶点已输出非零坐标，状态为 `ok`。
- 防复发规则：如果 attributes.json 中存在明显的 float3 attribute（如 `R32G32B32_FLOAT`）且 OBJ 全零，必须优先检查 semantic/role 映射；不能把缺少 POSITION semantic 等同于没有 position 数据。

## 2026-06-07 - texture library key 截断导致不同 DDS 共用同一文件名
- 现象：`validate_extraction.py` 对 EID 7955 报告 `B8G8R8A8_TYPELESS_000001.dds` hash mismatch；多个不同 resource 的 manifest 都指向同一 DDS 文件。
- 根因：`library_db.make_asset_key()` 只取 digest 前 16 字符，但 `extract_textures.py` 传入的 digest 文本形如 `B8G8R8A8_TYPELESS_<sha256>`，前 16 字符只包含格式名，导致同格式不同内容的 texture key 冲突。
- 修复：`extract_textures.py` 改为先对 `format|dds_sha256` 计算 sha256，再传入 `make_asset_key()`；清空 Output 后重跑 EID 7643/7955，B8G8R8A8_TYPELESS 正确生成 3 个不同 DDS 文件，验证通过。
- 防复发规则：所有库 key 输入必须是实际 hash 字符串，不允许直接拼接带长公共前缀的文本再截断；新增/修改 key 规则后必须清空输出重跑并执行 hash 校验。

## 2026-06-07 - material_hlsl_slice.py 只保留最后一次赋值导致贴图采样缺失
- 现象：用户发现源 PS HLSL 中 `_15.Load(...)` 明显参与计算，但 `material_slices.hlsl` 的 `MaterialTextureSamples` 只有一个 `float Sample_1`，没有 `_15` 对应的采样/Load，也缺少 `_16/_17` 的 SampleLevel。
- 根因：`parse_assignments()` 对同名临时变量只保存最后一条赋值；反编译 HLSL 中 `_476/_477/_478/_479`、`_659/_660/_661` 等变量在 if/else 两个分支都有赋值，最后一条 else 常量赋值覆盖了 if 分支中的 texture Sample 依赖，导致依赖闭包漏掉 `_15.Load`、`_16.SampleLevel`、`_17.SampleLevel`。
- 修复：`parse_assignments()` 改为保存每个 symbol 的所有赋值记录；`dependency_closure()` 遍历同一 symbol 的所有赋值，保证分支内 texture indirection 也进入切片；`substitute_index_expr()` 使用 latest assignment 做索引符号化。重生成 EID 7643 后 `MaterialTextureSamples` 包含 4 个样本：`_15.Load`、`_12.SampleBias`、`_17.SampleLevel`、`_16.SampleLevel`，验证通过。
- 防复发规则：对反编译 HLSL 做依赖切片不能把 SSA-like 临时变量简单当作单赋值；遇到分支/phi 变量必须保留所有赋值候选，否则会漏掉分支内 texture/buffer 依赖。

## 2026-06-07 - SVT 重建两次错误
### 第一次：全局 page table 当作单张纹理
- 现象：1024 preview 全错，块状乱图。
- 根因：page table 是 128x128 全局共享表，这个 mesh 只使用其中 [16..31, 112..127] 的 16x16 区域（page_base_x=16, page_base_y=112, pages_per_axis=16 from cbuffer b2）。
- 修复：解析 cbuffer _36_m0[0..1] 获取 pages_per_axis 和 page_base，只提取对应区域。

### 第二次：未处理 mip level，每 block 都是完整贴图（低分辨率重复）
- 现象：还原出 256 个 pages，每 page 内部内容正确但每 4x4 blocks 是同一个 tile 的拷贝。
- 根因：page table 本身有 8 个 mip 级别（_15.Load 第三参数是 mip index）。该帧 GPU 只加载了 mip=2/mip=3 的 pages。mip=2 意味着一个物理 tile 覆盖 4x4 虚拟 page 位置（即 mip_bits=2 → scale=4 → 每物理 128px tile 覆盖虚拟 512px 区域）。旧代码直接 1:1 铺贴导致 4x4 区域都复制同一个低分辨率 tile，看起来像块状重复。
- 修复：reconstruct_svt.py 改为按各 mip 级别查找最高分辨率 page，并按 2^mip_bits 做 upscale 最近邻采样。当前帧所有 pages 都是 mip=2/3，因此还原结果仍是上采样低分辨率，这是捕获帧限制，非逻辑错误。
- 防复发规则：SVT page table 的 Load 第三参数是 mip index；descriptor 的 mip_bits 字段决定物理 tile 对应虚拟空间的尺度（2^mip_bits 虚拟像素 = 1 物理像素）；如果捕获帧只有高 mip pages（低分辨率），还原效果必然低分辨率，需在完整 mip 0 加载的帧上才能还原高清纹理。
